# Parity contract

Both builds must be strict supersets of the players they replace, and equal to each other. This
file is the contract. Each row is a feature or behaviour of one original (or both). A row is
ticked only when the check named in its Evidence column passes against **both** builds: the app
(`dist/`, served) and the single file (`index.html`, opened from `file://`).

- **App** = `realistic-vinyl-player-claude` (Vite app).
- **H1** = `realistic-vinyl-player-claude-html-1` (single file).
- **Pinned to** `docs/reference-stamp.json`, written 2026-10-26 (see the file for the time): App `b602df9` with
  working-tree diff `b89198bdb5ccc681`, H1 `4191965` with diff `f060b971e680ec19`.
  `node scripts/reference-stamp.js --check` runs at every gate. If an original changes, its new rows are added here before the gate closes. H1's Winamp
  round (graphic EQ, desktop, seven visualizer styles) is included: rows H44, H45 and C13.

Evidence names:

- `u:` a Vitest file in `tests/`
- `b:` a browser check in `scripts/`, run on both builds
- `h:` an assertion in html-2's ported `test/verify.js` or `test/extra.js`
- `s:` a reviewed screenshot in `docs/screenshots/`

"Was" columns quote where the behaviour lived, so a reviewer can compare.

Data is never migrated between profiles. New fields are additive; an original that reads the
same keys ignores them. Evidence: `b:check-storage` (writes with the original's shape, reloads,
reads back) and `h:settings survive a reload`.
